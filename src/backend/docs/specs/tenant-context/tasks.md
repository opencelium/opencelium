# Tenant context: the tasks

Each task is 1 pull request. The size rule of a task is in CONTRIBUTING.md, section 5.3.
The status line is the only status in this folder.
A task that changes the behaviour of a criterion changes spec.md in the same PR.

## Task 1: feat(core): bind the current tenant and show it in each log line
- **Criteria:** TC-01, TC-03, TC-05, TC-08, TC-09
- **Function:** Each application log line of core shows the tenant ID. The first admin of the start and the lock task run for the tenant of the self-host installation. In the cloud mode the lock task does not run (plan decision 6). TC-01 gets its request test in task 4, and TC-05 gets its form test in task 4. TC-08 gets its test with a tenant document in task 2.
- **Tests:** `TenantIdTest` (unit): isReservedIsTrueWhenTheValueIsSelfHostTenantOrSystem, isReservedIsFalseWhenTheValueIsATenantOfTheServicePortal; `TenantRunnerTest` (unit): runGivesTheTenantToTheTaskWhenTheModeIsSelfHost, runStartsNoTaskWhenTheTenantIsNotTheSelfHostTenant, runGivesTheTenantOfTheRecordWhenTheModeIsCloud, runStartsNoTaskWhenTheTenantIsReservedInCloudMode, runStartsNoTaskWhenADifferentTenantIsBound, runGivesTheTenantToTheTaskWhenTheSameTenantIsBound, runRemovesTheTenantWhenTheTaskFails, runWritesTheMdcKeyWhenTheTaskRuns; `CurrentTenantTest` (unit): getGivesTheBoundTenantWhenTheTenantRunnerRunsTheTask, getStopsWithNoCurrentTenantWhenNoTenantIsBound; `DefaultsEnvironmentPostProcessorTest` (unit): applyDefaultsGivesTheSelfHostLogPatternWhenTheModeIsSelfHost, applyDefaultsGivesTheCloudLogPatternWhenTheModeIsCloud, applyDefaultsKeepsTheLogPatternWhenTheOperatorSetsOne; `TenantLogLineTest` (full application): startWritesTheTenantIdIntoEachLineWhenTheModeIsSelfHost, runWritesTheBoundTenantIntoTheLineWhenTheModeIsCloud, startWritesNoTenantIdWhenTheModeIsCloud; `SetupCompletionRunnerTest` (full application): runMakesTheAdminForTheSelfHostTenantWhenTheModeIsSelfHost; `GeneratedPasswordLockJobTest` (full application): lockExpiredGeneratedPasswordsRunsForTheSelfHostTenantWhenTheModeIsSelfHost, lockExpiredGeneratedPasswordsLocksNoUserWhenTheModeIsCloud; `MongoStepEnvironmentTest` (unit): runShowsNoLogPatternDefaultWhenItAppliesTheDefaults
- **Hand test:** 1. Start `java -jar oc-app.jar` with `SPRING_MONGODB_URI=mongodb://localhost:27017/oc_hand`. 2. The log has the `(default)` line of `logging.pattern.correlation` with the value `[%X{tenant:-self-host-tenant}] `. 3. Each log line shows `[self-host-tenant]`. Stop core. 4. Run `mongosh oc_system` and insert 1 user: `db.users.insertOne({tenantId: "acme", username: "u1", roles: [], mustChangePassword: true, temporary: false, locked: false, passwordIssuedAt: ISODate("2020-01-01"), createdAt: ISODate("2020-01-01")})`. 5. Start core with `OPENCELIUM_DEPLOYMENTMODE=cloud`, `SPRING_MONGODB_URI=mongodb://localhost:27017/oc_system` and `OC_MASTER_KEY` from `openssl rand -base64 32`. 6. Each log line shows `[-]`, and no line says "Locked user". 7. In `mongosh`, the user `u1` has `locked: false`.
- **Size:** approximately 200 lines
- **Depends on:** nothing
- **Status:** done

- **Hand test:** 1. Drop the database `oc_hand`. Start core with `SPRING_MONGODB_URI=mongodb://localhost:27017/oc_hand`, then stop it. 2. Run `mongosh oc_hand`: `db.users.find({}, {tenantId: 1, username: 1})` shows the admin with `tenantId: "self-host-tenant"`. 3. Insert the user `u1` of task 1 with `tenantId: "self-host-tenant"`. 4.
